# 领域资料

联盟机构分别管理本地医疗数据；协作控制信息只涉及机构身份、执行许可、数据摘要及回执。

`contracts/entities.json` 保存外部数据的首批交换字段。来源编号仅表示提交方对同一记录的识别符，示例文件不包含真实个人资料。运行时持久化文件由 `DATABASE_PATH` 决定；时间字段使用带时区偏移的 ISO 8601 字符串。

## 跨机构术语与用途协议

护理指标与病种术语在各机构（含东盟机构）的表述不一致：名称相同的指标可能定义不同。本服务为牵头医院提供术语与用途的协议登记与发放能力，让各方在比较指标之前先对齐定义。

### 边界

- 中心只保存本地字段定义的**不可逆摘要**（`sha256:<64 位小写十六进制>`）、适用语言、单位与授权用途；不接收原始病历，不执行模型训练。
- 所有写接口按契约字段严格解码，契约之外的字段一律拒绝，从接口形状上防止误收患者数据。
- 患者数据始终留在各机构本地，本服务不承载任何结果计算。

### 角色（请求头 `X-Actor-Institution` + `X-Actor-Role`）

- `data-steward`：机构数据管理员。提交字段摘要、发起映射与新版本、登记歧义说明。
- `clinical-lead`：临床负责人。签署映射版本、推翻翻译、登记撤回。
- `lead-center`：牵头医院协调方。把生效版本发放到指定协作任务。
- `regulator`：监管人员。只读，沿已发布指标溯源签署与撤回范围。

### 流程与不变量

1. 各机构提交本地字段定义摘要（`POST /term-submissions`），同一机构内 `local_field_ref` 唯一；定义修订后以新字段标识再次提交。
2. 一方数据管理员就两份分属不同机构的提交发起映射（`POST /mappings`），产生待确认的第 1 版；同一映射的两侧机构集合不可变更。
3. 两侧机构的临床负责人各自签署同一版本（`POST /mappings/{ref}/versions/{n}/confirmations`），双方签署齐全后版本生效（`effective`）。每机构每版本只能签署一次。
4. 牵头中心仅能把生效版本发放到指定协作任务（`POST /tasks/{task}/catalog-grants`）。
5. 合作方查询任务目录（`GET /tasks/{task}/catalog`）时只能看到本机构参与的映射及其歧义说明；条目状态为 `active` / `superseded` / `overturned` / `withdrawn`。
6. 术语翻译被推翻（`POST .../overturn`）或机构撤回（`POST .../withdrawals`，携带任务/用途/时间范围）时，历史版本、双方签署与已发放记录**全部保留**，只追加新记录；使用过旧版本的历史结果可沿 `(indicator_key, version)` 永久回查。
7. 监管人员沿已发布指标溯源（`GET /indicators/{key}/lineage`），可看到每个版本的签署机构、签署人、发放去向与后来的撤回范围。

### 存储

SQLite 单文件，服务启动时自动应用 `migrations/` 下未执行的迁移。除映射版本的状态推进外，所有表只增不删。
